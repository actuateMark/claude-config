# claude-config

Mark Barbera's reusable Claude Code configuration. Lives at `~/.claude/` on the host. This repo is the disaster-recovery copy — clone it on a new machine, reinstall Claude Code, recreate secrets, and you have your full skill / agent / hook setup back.

## What's tracked

| Path | Purpose |
|---|---|
| `CLAUDE.md` | Global instructions all sessions inherit |
| `kb-config.md` | KB topic structure + conventions |
| `policy-limits.json` | Tool / capability restrictions |
| `settings.json` | Hooks wiring + permission allowlist (host paths are mork-specific — review before reusing) |
| `agents/` | Custom subagent definitions (R&D prospector / source-reader / kb-scribe / nrql-investigator / etc.) |
| `skills/` | Custom skill definitions invoked via `/skill-name` |
| `hooks/` | SessionStart / Stop hook scripts (session-claims, daily-scope/wrap reminders) |

## What's deliberately NOT tracked

The `.gitignore` is **deny-by-default + explicit allowlist**. Anything not in the list above is ignored. Specifically excluded:

- `.credentials.json` — Anthropic API auth (regenerated by `claude` on first run)
- `settings.local.json` — host-specific permission overrides
- `projects/`, `tasks/`, `telemetry/` — runtime session state
- `cache/`, `downloads/`, `paste-cache/`, `backups/`, `file-history/`, `session-env/`, `plugins/` — runtime data
- `history.jsonl` — session history (contains conversation logs and any secrets surfaced during sessions)
- `plans/` — in-progress planning notes (often stale, sometimes contain secrets)

## Disaster recovery — set up Claude Code on a new machine

1. Install Claude Code per the official installer (it'll create `~/.claude/` and ask for first-run auth).
2. After first-run auth, **back up** the freshly-created `.credentials.json` somewhere outside this repo.
3. `cd ~/.claude && git init && git remote add origin <this-repo>.git && git pull origin main`
   - This drops the tracked files into place alongside the auto-generated runtime state.
4. Re-authenticate the MCP servers you use (`claude mcp add ...` or via UI). MCP credentials live in `.credentials.json`, not in this repo.
5. If you're using session-claims hooks and they need to read mark-todos: clone the KB repo separately into `~/Documents/worklog/knowledgebase/` (or set `KB_ROOT` in your shell to wherever it lives on this machine).
6. Verify with `claude` and run a no-op skill (`/recap` is a fast smoke test).

## Secrets that need manual recreation

| Secret | Where it lives | Recreate by |
|---|---|---|
| Anthropic API auth | `~/.claude/.credentials.json` | Run `claude` and complete first-run flow |
| NR API key | `~/.config/newrelic/key` | Mint at one.newrelic.com → API keys → user key |
| AWS Roles Anywhere cert/key | `~/.config/aws-rolesanywhere/` (minipc only) | See `2026-04-27_iam-rolesanywhere-minipc` KB note |
| `gh` token | `~/.config/gh/hosts.yml` | `gh auth login` |
| MCP server tokens | varies per server | Re-auth via Claude Code UI |

## Updating

- Edit files in place under `~/.claude/`. Don't add new top-level files unless you also un-ignore them in `.gitignore` — the allowlist is intentionally tight.
- Test changes locally first; the configuration affects every Claude Code session this user starts.
- Skill / agent edits should be cross-checked: does the skill's `SKILL.md` still describe what the code does? Are there host-specific paths that need to be parameterised before pushing?
